# تصمیم‌ها و ابهام‌های محصول

## پاسخ‌های مالک — ۲۰۲۶-۱۱-۲۵

- Google Calendar: همگام‌سازی دوطرفه فقط برای ایونت‌ها و فقط با تقویم اصلی حساب Google انجام شود. حذف یک‌طرفه و هر تعارض ویرایش/حذفِ هم‌زمان نیازمند تأیید کاربر است؛ هیچ حذف یا بازنویسی خودکار در این موارد انجام نشود.
- مقصد انتشار سایت فقط GitHub Pages است. API لازم برای قابلیت‌های متصل روی هاست `toojibee.ir` می‌ماند؛ سایت Pages باید پس از آماده‌شدن CORS و API به آن وصل شود.
- قابلیت‌های وابسته به سرویس نیز در دامنهٔ کار می‌مانند و انتشار نهایی پس از آماده‌شدن آن‌ها انجام می‌شود. این پاسخ به‌تنهایی ارائه‌دهندهٔ نقشه/پرداخت/AI، اعتبارنامهٔ OAuth یا سیاست‌های باز D08 و D12 تا D22 را تعیین نمی‌کند.
- پنل هاست در مرورگر مالک وارد شده است، اما ابزار کنترل دسکتاپ در نشست ۲۰۲۶-۱۱-۲۵ timeout داد؛ دسترسی عملی برای آپلود API هنوز تأیید نشده است.

## پاسخ‌های مالک — ۲۰۲۶-۱۱-۱۷

- ورود با موبایل فعلاً متوقف بماند؛ این تصمیم فقط همین قابلیت را از اجرای فعلی خارج می‌کند.
- تعارض ویرایش/حذف در همگام‌سازی Google Calendar برای تصمیم کاربر نگه داشته شود؛ هیچ طرف به‌طور خودکار بازنویسی نشود.

## پاسخ‌های مالک — ۲۰۲۶-۱۱-۱۶

- تکرار داخل بازه: یک فعالیت با یادآوری در هر نوبت؛ وضعیت انجام مجزا برای نوبت‌ها لازم نیست. انتهای بازه مطابق مثال درخواست شامل است.
- ساعت اعلان مناسبت‌ها: کاربر هنگام فعال‌سازی ساعت را انتخاب می‌کند؛ ساعت پیش‌فرض خودکار تعیین نمی‌شود.

## به‌روزرسانی ۲۰۲۶-۱۱-۱۶

- مالک ترتیب اجرای مرحله‌ای را تأیید کرد؛ C01 قبلی دیگر مانع توسعهٔ همین دامنه نیست. دستور جدید، تم/فروشگاه/درآمدزایی/لندینگ/اجتماعی را از این آپدیت خارج می‌کند و بر C03/C05/C06 قبلی مقدم است.
- D01 در این مرحله: حفظ قواعد موجود بدون ساعت؛ خط زمانی ساعت‌دار با گروه‌های ساعتی و ترتیب زمان واقعی. پین و انجام، ترتیب ساعت‌دارها را جابه‌جا نمی‌کنند. این انتخاب اجرایی عامل است، نه تأیید نهایی UI توسط مالک.
- Undo فقط حذف و دقیقاً ۵ ثانیه است؛ پرسش قدیمی دامنهٔ Undo در D03 با درخواست جدید پاسخ داده شد. Google Sync دوطرفه و مخصوص Event است؛ سیاست حذف/تعارض D08 هنوز باز است.
- درخواست تازهٔ مناسبت باستانی، منبع پژوهشی و ساختار داده را تعیین می‌کند؛ زمان اعلان همچنان نیازمند تصمیم مالک است.

تاریخ: ۲۰۲۶-۱۱-۱۵. `Confirmed instruction` یعنی دستور روشن مالک در همین درخواست، نه تأیید پیاده‌سازی. پیشنهادهای فنی زیر تصمیم محصول محسوب نمی‌شوند.

## پیشنهادهای فنی بدون تغییر معماری فعلی

- PHP هدف سازگار با هاست فعلی باقی بماند؛ Django طبق قرارداد مشترک همگام نگه داشته شود. انتخاب انتقال هاست/حذف یکی از بک‌اندها فعلاً مطرح نیست.
- جدول entitlement و تراکنش پرداخت سمت سرور باشد؛ `state.store`، localStorage یا فلگ UI سند خرید نیستند.
- قالب دادهٔ نسخه‌دار برای تکرار، مجوزها و میزکارها؛ Migration افزایشی و خواندن داده‌های قبلی پیش از تغییر نگارش.
- Google، AI و گزارش SEO پشت API خود پروژه؛ کلیدها خارج از web root و Git. استثناهای لازم برای push/redirect با توضیح صریح مستند شوند.
- انتخاب کتابخانه یا سرویس جدید تنها با دلیل فنی مستند؛ در این بررسی هیچ وابستگی اجرایی به پروژه اضافه نشده است.
