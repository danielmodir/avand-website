## تصمیم‌های قطعی مالک

- فقط ایونت‌ها و فقط تقویم اصلی Google، با تبادل دوطرفه.
- اتصال اول: ادغام خودکار ایونت‌های موجود دو طرف.
- حذف یک‌طرفه و ویرایش هم‌زمان: انتخاب صریح کاربر.
- تکرار شمسی/قمری ناسازگار در توجیبی باقی بماند.
- سایت روی GitHub Pages و API روی هاست toojibee.ir؛ مالک انتشار را مجاز کرده است.

## انجام‌شده و ثبت‌شده در کد

- OAuth مستقل Calendar با state یک‌بارمصرف، PKCE و scope محدود owned-events.
- رمزگذاری refresh token و cache رمز‌شدهٔ access token با انقضا؛ migrationهای PHP تا v31.
- خواندن صفحه‌بندی‌شدهٔ تقویم اصلی، نگاشت ایونت و تکرارهای سادهٔ سازگار.
- مقایسهٔ سه‌طرفه، طرح ادغام و محافظ حذف و شناسه‌های تکراری.
- endpointهای status/connect/callback/preview/apply/disconnect؛ اجرای یک اقدام با نسخهٔ سند و etag.
- کنترل اتصال و همگام‌سازی در تنظیمات تقویم، نمایش دو نسخه و انتخاب دستی تعارض، متن فارسی/انگلیسی.
- آغاز ادغام پس از اتصال، بررسی دوره‌ای هنگام بازبودن برنامه و پس از ذخیرهٔ ایونت.
- محافظت از ذخیرهٔ سند هنگام رندر و توقف ادامهٔ همگام‌سازی در صورت ویرایش محلی.
- نسخهٔ asset برنامه 2026-11-26.1. کد روی شاخهٔ GitHub قرار دارد.

## شواهد آزمون

- Node: 64 آزمون موفق.
- مرورگر محلی: ۸ حالت عرض 360/1280، زبان fa/en و روشن/تاریک؛ انتخاب دستی و اقدام خودکار با API شبیه‌سازی‌شده موفق، بدون خطای صفحه یا درخواست خارجی.
- PHP CI اجرای 45784711334 روی commit 33a0b44 موفق: lint، مجوز، migration، cache، نگاشت، طرح ادغام و قواعد apply.
- این آزمون‌ها اتصال واقعی Google یا نوشتن واقعی روی تقویم را ثابت نمی‌کنند.

## انجام‌نشده و مانع انتشار

- Google Cloud project، فعال‌سازی Calendar API و ساخت/تنظیم OAuth client انجام نشده‌اند.
- اعتبارنامه‌ها روی هاست قرار نگرفته‌اند؛ رضایت واقعی Google، callback و تبادل واقعی رویداد آزموده نشده‌اند.
- کنترل مرورگر حساب بارها پیش از دریافت فهرست تب‌ها با `service_info` timeout متوقف شد؛ مالک گفته اتصال را دوباره وصل می‌کند. کلید یا گذرواژه را در چت نخواه.
- API روی هاست و این قابلیت روی Pages منتشر نشده‌اند؛ config فعلی Pages همچنان آفلاین است.
- همتای Django این قابلیت پیاده نشده است. APK جدید ساخته نشده است.
- آزمون یکپارچهٔ اجرای apply با provider شبیه‌سازی‌شده، خطای شبکه پس از نوشتن و درخواست‌های هم‌زمان هنوز لازم است.
- snapshot کامل برای هر اقدام دوباره خوانده می‌شود و سقف ۱۰هزار رویداد دارد؛ برای تقویم بزرگ به cache/incremental sync و batch نیاز است.
- سری‌های Google دارای exception اکنون از ادغام خودکار خارج می‌شوند؛ نگاشت کامل این سری‌ها هنوز پیاده نشده است.
- migrationهای شاخهٔ مالی هم‌زمان شماره‌های مشابه دارند؛ پیش از هر ادغام مشترک، ترتیب migrationها را تطبیق بده.

## ادامهٔ کار

ابتدا موارد داده و هم‌زمانی بالا را با آزمون واقعی رفع کن. سپس با دسترسی مرورگر
حساب، Google Cloud و تنظیمات امن هاست را تکمیل کن، از دادهٔ هاست پشتیبان بگیر،
API را مستقر کن و CORS مبدأ دقیق Pages را بررسی کن. اتصال واقعی را روی حساب
آزمایشی برای ساخت، ویرایش، حذف، تعارض و قطع/وصل اینترنت بررسی کن. فقط پس از
موفقیت، config Pages را به API وصل و منتشر کن. نتیجه را با لینک deployment و
آزمون‌ها گزارش بده؛ صرف push شدن شاخه را فعال‌شدن قابلیت معرفی نکن.
