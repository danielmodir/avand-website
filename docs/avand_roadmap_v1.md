# نقشه راه ساخت آوند (Avand) — از صفر تا عرضه

## فاز ۱: اعتبارسنجی ایده (Idea Validation)
- گفتگو با کاربران هدف بالقوه (دانشجویان، افرادی که دنبال self-improvement هستن) برای سنجش نیاز واقعی
- بررسی رقبا (Habitica، Notion، Todoist، Fabulous) — نقاط قوت/ضعفشون
- تعریف اولیه‌ی Value Proposition: چرا آوند و نه رقبا؟

## فاز ۲: سناریونویسی و تعریف محصول
- User Persona ها (کاربر آوند کیه؟)
- User Journey / سناریوهای اصلی استفاده
- اولویت‌بندی فیچرها (چی MVP هست، چی نیست)

## فاز ۳: تعیین دامنه‌ی MVP
- انتخاب حداقل ماژول‌هایی که باید در نسخه‌ی اول باشن
- تصمیم درباره‌ی فیچرهای فاز بعد (AI، اجتماعی و...)

## فاز ۴: طراحی UI/UX
- Wireframe (طرح ساده و بدون جزئیات بصری)
- Prototype قابل کلیک (Figma یا مشابه)
- طراحی نهایی بصری (UI Design)

## فاز ۵: انتخاب استک فنی
- فریم‌ورک موبایل (مثل React Native یا Flutter)
- بک‌اند و دیتابیس (مثل Firebase یا Node+Postgres)
- تصمیم درباره‌ی نیاز به API اختصاصی

## فاز ۶: توسعه (Development)
- توسعه‌ی تدریجی طبق اولویت فیچرها
- معمولاً به‌صورت Sprint یا مرحله‌ای

## فاز ۷: زیرساخت‌های مورد نیاز (کلی)
- **هاست/سرور بک‌اند** — جایی که داده‌ها و منطق برنامه اجرا می‌شه
- **دیتابیس** — ذخیره‌ی اطلاعات کاربران، Task ها، Habit ها و...
- **دامنه (Domain)** — اگه وب‌سایت یا صفحه‌ی معرفی هم بخوای
- **حساب توسعه‌دهنده در استورها** (Google Play Console، Apple Developer) — برای انتشار اپ
- **سرویس‌های جانبی احتمالی** — مثل Push Notification، Analytics، یا سرویس AI

## فاز ۸: تست
- تست داخلی (Internal Testing) توسط تیم/خودت
- رفع باگ‌ها و مشکلات اولیه

## فاز ۹: بتا (Beta)
- انتشار محدود برای گروه کوچیکی از کاربران واقعی
- جمع‌آوری بازخورد و اصلاح

## فاز ۱۰: عرضه‌ی نهایی (Launch)
- انتشار عمومی در استورها
- شروع بازاریابی و جذب کاربر

---

> این یه نقشه‌ی کلیه، نه ترتیب سفت‌وسخت — بعضی فازها (مثل UX و انتخاب استک) می‌تونن هم‌زمان پیش برن.
