# آوند (Avand) — فاز ۲: سناریونویسی و تعریف محصول

> وضعیت: هر سه بخش فاز ۲ (Persona، Journey، اولویت‌بندی فیچرها) تکمیل شد. چند مورد به‌صورت آگاهانه برای فازهای بعد باز مونده (در بخش «نکات باز» مشخص شده).

---

## ۱. User Persona

با توجه به بحث‌ها، مخاطب آوند از نظر فنی می‌تونه «هر کسی» باشه، اما برای طراحی و اولویت‌بندی فیچر، دو پرسونای اصلی تعریف شد:

### پرسونا ۱: «دانش‌آموز / دانشجو» (۱۵-۲۴ سال)

| ویژگی | توضیح |
|---|---|
| زیرگروه‌ها | دانش‌آموز دبیرستانی (برنامه‌ریزی کنکور) + دانشجو (مدیریت زندگی دانشگاهی) |
| هدف اصلی از آوند | ترکیبی: مدیریت زمان درس/برنامه‌ریزی تحصیلی + ساختن عادت (ورزش، مطالعه و...) |
| وضعیت نظم فعلی | ترکیبی — نزدیک امتحانات/کنکور منظم‌تر، در دوره‌های عادی بی‌نظم‌تر |
| آشنایی با تکنولوژی | راحت با اپ‌ها؛ قبلاً از ابزارهای مشابه استفاده کرده |
| نقطه‌ی درد اصلی | کارها و عادت‌ها پخش‌اند تو چند اپ/دفترچه؛ زیر فشار درسی، عادت‌ها اولین چیزیه که ول می‌شه |
| دلیل انتخاب آوند | یه‌جا هم برنامه‌ریزی درسی/کنکور داشته باشه هم پیگیری عادت |

### پرسونا ۲: «شاغل / بزرگسال علاقه‌مند به توسعه‌ی فردی» (۲۵-۵۰ سال)

| ویژگی | توضیح |
|---|---|
| هدف اصلی از آوند | ترکیبی: تعادل کار/زندگی + ساختن عادت (سلامت، مالی و...) |
| وضعیت نظم فعلی | ترکیبی — روزهای سبک‌تر منظم‌تر، روزهای پرمشغله عادت‌ها کنار می‌ره |
| آشنایی با تکنولوژی | راحت با اپ‌ها؛ قبلاً از ابزارهای مشابه استفاده کرده |
| نقطه‌ی درد اصلی | بین کار، زندگی شخصی و اهداف بلندمدت گیر می‌کنه؛ ابزارهای فعلی جدا از همن |
| دلیل انتخاب آوند | یه ابزار واحد برای کارهای روزمره و اهداف بلندمدت شخصی |

**تصمیم اولویت:** هر دو پرسونا هم‌زمان برای MVP اولویت دارن (نه یکی مقدم بر دیگری).

**ریسک ثبت‌شده:** بازه‌ی سنی پرسونای دوم (۲۵-۵۰) هنوز خودش وسیعه؛ ممکنه بعداً (مثلاً در تست کاربری) نیاز به شکستن به زیرگروه‌های دقیق‌تر باشه.

## ۲. User Journey

یک Journey مشترک بین دو پرسونا تعریف شد، با محدوده‌ی **از نصب اپ تا پایان هفته‌ی اول استفاده**.

| مرحله | کار کاربر | فکر/احساس کاربر | نقطه‌ی ریسک |
|---|---|---|---|
| ۱. کشف | اپ رو در استور یا از طریق معرفی پیدا می‌کنه | «این یکی چه فرقی با بقیه داره؟» | توضیح نامشخص در استور → رد شدن |
| ۲. نصب و باز کردن اول | اپ رو دانلود و باز می‌کنه | کنجکاو ولی بی‌حوصله برای مراحل طولانی | Onboarding طولانی → ریزش زودهنگام |
| ۳. Onboarding | هدف‌هاش رو مشخص می‌کنه | «امیدوارم پیچیده نباشه» | تنظیمات زیاد قبل از دیدن ارزش واقعی |
| ۴. اولین آیتم | اولین Task یا Habit رو می‌سازه | «باید ببینم واقعاً کمک می‌کنه» | ساخت آیتم اول سخت/گیج‌کننده |
| ۵. روزهای ۱-۳ | نوتیف می‌گیره، تیک می‌زنه یا فراموش می‌کنه | حس اولیه‌ی موفقیت یا بی‌تفاوتی | نوتیف مزاحم یا بی‌فایده |
| ۶. اولین باز شدن Report/Chart | پیشرفتش رو چک می‌کنه | «جالبه» یا «فایده‌ای نداشت» | گزارش بی‌معنی یا در زمان نامناسب |
| ۷. روزهای ۴-۷ (افت احتمالی) | یه روز یادش می‌ره یا حوصله نداره | احساس شکست کوچیک | بیشترین نقطه‌ی ریزش کاربر |
| ۸. پایان هفته‌ی اول | تصمیم ضمنی: ادامه بده یا حذف کنه | «ارزششو داشت؟» | اگه حس نکرده بهتر از روش قبلیه، حذف می‌کنه |

## ۳. اولویت‌بندی فیچرها — دامنه‌ی MVP

### ماژول‌های داخل MVP

```
آوند (MVP)
│
├── Task
│   ├── افزودن / ویرایش / حذف
│   ├── برچسب کاتگوری (ساده، فقط لیبل — بدون پوشه/مدیریت کاتگوری)
│   ├── توضیحات (متن آزاد)
│   ├── پیوست فایل/عکس (حداکثر ۳ عدد)
│   ├── ستاره‌دار / پین کردن
│   ├── علامت‌گذاری «انجام‌شد» / «انجام‌نشد» (بدون انتقال خودکار به روز بعد)
│   ├── ریزتسک (Subtask)
│   │   ├── حداکثر ۳ ریزتسک برای هر Task
│   │   └── فقط وضعیت انجام‌شد/نشد
│   ├── تعیین زمان
│   │   ├── تک‌روز (انتخاب از تقویم کوچک)
│   │   └── بازه‌ی روزی
│   ├── تکرار خودکار
│   │   ├── حالت ۱: بازه‌ی عددی (هر روز، یک روز درمیون، هر ۳ روز، ... تا ۷ روز)
│   │   └── حالت ۲: انتخاب روزهای مشخص هفته
│   └── نوتیفیکیشن
│       ├── نوع ۱: یادآوری در زمان مشخص
│       ├── نوع ۲: یادآوری تکرارشونده از لحظه‌ی شروع (هر ۱ ساعت، هر ۲ ساعت، ...)
│       └── متن دلخواه نوتیف
│
├── Habit
│   ├── افزودن / ویرایش / حذف
│   ├── تیک روزانه
│   ├── تعیین روزهای فعال (تکرار خودکار)
│   │   └── کاربر مشخص می‌کند این Habit کدام روزها/چه بازه‌ای فعال باشد (مثلاً یک روز درمیان یا روزهای خاص هفته)
│   └── نوتیفیکیشن (همان دو نوع Task + متن دلخواه)
│
├── Calendar / Planning
│   ├── نمای روزانه
│   ├── نمای هفتگی
│   ├── نمای ماهانه
│   └── نمایش Task / Habit / Event روی تقویم
│
└── Event
    ├── افزودن / ویرایش / حذف
    ├── تعیین زمان (تک‌روز / بازه‌ی روزی — مشابه Task)
    ├── تکرار خودکار (همان دو حالت Task)
    └── نوتیفیکیشن (همان دو نوع Task + متن دلخواه)
```

### خارج از MVP (برای فازهای بعد)
Challenge، Journal، Reports/Charts (حتی نسخه‌ی ساده)، AI/Chatbot، Category کامل (پوشه‌سازی)، Tools تخصصی، Tool Store، Social
